# Repository Guidelines

strata-models: the one service that owns the GPU and serves local models to every app (see README.md). Python backend (FastAPI + CLI, `src/stratamodels/`), React frontend on strata-react (`web/`), a standalone client package (`client/`), hermetic unit and integration suites, coverage ratchets, GitHub Actions CI.

- Model code lives in `src/stratamodels/runtimes/` (one module per runtime: `load`, `run`, `unload`; heavy imports inside `load`). The queue and VRAM budget are `scheduler.py`; job rows `store.py` (omarchy-db, schema `stratamodels`, every table in `db/models.py`, see docs/database.md); roles and models `registry.py`, read from the database, seeded from `models.toml`. Tests never touch the shared database (conftest pins a tmp SQLite URL); only the deployed service migrates the live one. A new role = a runtime module, an entry in `runtimes.RUNTIMES`/`NEEDS`, a role in `models.toml`, a test in `tests/gpu`.
- The client (`client/strata_models_client`) is standard library only: keep it that way, apps install it into their own venvs.

- Python application code lives in `src/stratamodels/`; the React web app lives in `web/src/` and builds into `src/stratamodels/server/static/`, which `./strata-models serve` serves at `/`.
- Python tests live under `tests/`, grouped by type:
  - `tests/unit/`: fast, isolated tests of pure logic and mocked boundaries (synthetic data, fakes). No external processes or network.
  - `tests/integration/`: end-to-end tests that run the CLI (in-process and as a subprocess) and the FastAPI HTTP API over real on-disk state.
  - `tests/utils/`: shared helpers (`fakes.py` for HTTP/subprocess doubles). `tests/conftest.py` holds shared fixtures and makes every suite hermetic (isolated home and data dir, no network).
  - Read `tests/README.md` before writing any Python test: fixtures, conventions, file-ownership rules and the per-module coverage ledger.
- Web tests live in `web/tests/{unit,integration,utils}` (vitest; unit runs in node, integration in jsdom). Backend calls are mocked with msw (`web/tests/utils/server.ts`: every endpoint the app calls needs a handler there); read `web/tests/README.md` before writing any.
- Commands (Python, from the repo root, via `uv run ...` or the `./strata-models` / `strata-models.cmd` launchers; `uv sync` builds `.venv` from the committed `uv.lock`, `uv sync --group gpu` adds the model runtimes; `uv add <pkg>` / `uv add --group dev <pkg>` change dependencies, commit `pyproject.toml` and `uv.lock` together):
  - `scripts/check` is `uv run --locked strata-check` (from [strata-python](https://github.com/jburnhams/strata-python), read its AGENTS.md): `uv lock --check`, `ruff check`, `ruff format --check`, `pyright` and `ty`, then the unit tests with coverage. Run it before every commit (`--fast` skips the tests, `--fix` applies safe ruff fixes). Style is `ruff format` at line length 120. Pyright is strict for the files under `strict` in `pyproject.toml` (a ratchet: type a file fully, then add it; never remove one) and warns elsewhere.
  - `uv run pytest tests/unit --cov` runs the unit suite with coverage (random order via pytest-randomly; `-n auto` runs in parallel; `diff-cover` checks the lines a change touches).
  - `uv run pytest tests/integration -n auto` runs the integration suite.
  - `./strata-models doctor` checks the environment, runtimes and GPU; `./strata-models serve` runs the service on port 8366; `uv run pytest tests/gpu -s` runs the real runtimes on the GPU (not in CI).
- Commands (web, from `web/`): `npm install`, `npm run dev` (proxies `/api` to `./strata-models serve` on 8366), `npm run build` (writes into `src/stratamodels/server/static/`), `npm run typecheck`, `npm run test:unit` (node), `npm run test:integration` (jsdom + msw), `npm run test:coverage:gate` (unit + integration together, what CI gates on: floors in `web/coverage-floor.json`), `npm run test:coverage` (unit only, informational), `npm run test:coverage:all` (unit + integration, no gate).
- Python coverage is calculated from the unit suite only (`fail_under` in `pyproject.toml`). Web coverage is gated on unit + integration together (`web/coverage-floor.json`, read by `web/vitest.gate.config.ts`). Both floors only ratchet up.
- Style: dense, comment-the-why, long lines are fine (ruff line-length 400), pytest style tests (`def test_...` with `assert`; use `monkeypatch`/`tmp_path` instead of patching globals by hand).
- Cross-platform (Linux, macOS, Windows): OS differences (file locks, process liveness and termination, priority, how to start the CLI) live in `strata_python.oslib` (the shared library, no copy here); do not import `fcntl` or call `os.kill(pid, 0)` elsewhere (on Windows that terminates the process).
- Reverse-proxy support: the web build uses relative asset paths (`base: './'` in `vite.config.ts`) and `BASE` from the page URL (`web/src/api.ts` `withBase`): any URL the app builds for `fetch`, `<img>` or a link must go through `withBase`.
- CI is `.github/workflows/unit.yml` (`strata-check --fast` once, unit tests with coverage on Linux Python 3.11-3.13, macOS and Windows; web typecheck, coverage gate, build) and `integration.yml` (integration tests on Linux, macOS and Windows, web component tests, weekly). `upgrade-strata-python.yml` moves the `strata-python` pin weekly through a PR that has passed the gate; `.github/dependabot.yml` keeps everything else current (daily, minor and patch grouped, no ignores).
- Docs live in `docs/`: `overview.md` (design brief), `implementation-plan.md` (milestones and next steps), `progress.md` (log of findings and decisions), `prompts/` (unattended agent prompts for backend unit, integration and web tests).
